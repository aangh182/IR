# Taste
- When he wants to compare two approaches, prefers a parallel duplicate of the pipeline (its own config file and artifacts directory) so he can judge results himself, rather than a benchmark/AB-comparison mode bolted onto the existing pipeline. Judge-it-himself means run both on one real, realistically long video from the actual corpus (not a synthetic toy clip) and hand him the side-by-side output folders to eyeball, rather than declaring a winner from aggregate metrics. Confidence: 0.75
- Once he has eyeballed a comparison and says it's good, he wants the old/superseded implementation removed outright and the winner made the single main path — not kept alongside as a fallback or dual-backend option. Confidence: 0.6
- Once a specific model/tool has been settled on, wants the code written for that one choice only: no generic multi-backend switch (env-var `*_BACKEND` branches, `open_clip` vs `sentence_transformers` fallbacks) for options nobody is going to run — he reads the extra branch as leftover cruft ("chạy SigLIP2-384 thôi mà cái kia xong rồi mà"). Confidence: 0.7
- When he asks for a component (e.g. "làm ra một web ui đầy đủ"), wants the complete user-facing version built now; pushing back with a trimmed "core" scope plus deferral to a later phase reads as under-delivering. Confidence: 0.6
- When local state (a DB, index, artifact dir) is corrupted, prefers the blunt reset — delete the broken state and re-run the normal full pipeline command — over the assistant's surgical, step-by-step repair procedure (exact-row deletes, sequence resets, ordered `--only` runs). Confidence: 0.5
- Prefers written output in Vietnamese, including long-form docs and summaries, and expects documentation to land in the repo's existing `Doc/` folder alongside his other notes rather than a new docs directory or beside the code. Confidence: 0.6
- For performance work, wants measurement before modification: profile the real pipeline on a real video first and report the actual per-stage numbers so the real bottleneck is identified, rather than applying plausible-sounding optimizations from theory (and he expects suggestions to be validated/refuted against measurements rather than taken on faith). Confidence: 0.7
- Wants optimizations shipped incrementally: after the bottleneck is measured, land the feasible/safe high-impact changes now ("sửa những thứ khả thi trước") and start with conservative resource settings that he can ramp up later, instead of one big all-or-nothing rewrite or another round of analysis before touching code. Confidence: 0.6
- Wants long pipelines staged in phases so he can consume the important artifact early: the fast, high-value stage (e.g. shots + keyframes) should run across all videos and be committed first, with the slow tail (e.g. follow frames) as a separate later pass, so he can start working with the partial output while the rest still runs — rather than per-item interleaving that only finishes everything at the end. Confidence: 0.6
- Wants the web UI reachable at one obvious URL on the same port as the API (e.g. serving the built `web/dist` from FastAPI on 8000) rather than a separate Vite dev server on another port; "the page doesn't show" should be fixed by consolidating onto a single openable address, not by asking him to visit a different port. Confidence: 0.5
- Wants operational how-to (how to start the app and step-by-step how to use the UI, including the remote/SSH access path) written into the repo `README.md` so it's followable without him, rather than left implicit in chat or only in code. Confidence: 0.5
- For UI he uses repeatedly, wants the primary action reachable without scrolling: the main form/button should sit at the top or be pinned (sticky) inside a viewport-height scrolling column, not left at the bottom of a long page, and secondary bulk (payload previews, logs) collapsed by default so the panel stays compact. Confidence: 0.55
- Prefers a lean, uncluttered UI surface: drop the hint/helper and example-suggestion text ("bỏ mấy cái text gợi ý đi"), and constrain settings to a small fixed set of sensible presets (e.g. Top-K as a dropdown of 20/30/40/50) instead of free-form numeric inputs, with the main setting grouped next to the primary action. Confidence: 0.55
- Prefers a light theme for the web UI (warm light background, white panels, dark ink text, restrained accent) over a dark/console look. Confidence: 0.5
- Expects UI features he was told are "done" to actually work in the UI he is looking at: when he reports "có ctrl click được đâu", that's a correction for having verified only the backend endpoint/tests rather than confirming the served frontend (dev server / built bundle behind the API) really has the interaction. So check the code path the browser actually loads before declaring an interactive feature finished. Confidence: 0.55
- For a secondary view on the same screen (e.g. similar-frame results after Ctrl+click, neighboring keyframes after Shift+click), expects the main content area to be swapped in place with a clear Back control restoring the exact previous state, not the new results appended below in a separate area — leaving him unsure where the output appeared ("card mấy ảnh tương tự hiện ở đâu… đổi cái grid lúc đó… xong có nút back"). The replacement view should fill the whole grid with the full context rather than a few items: for a timeline he wants every keyframe in the window shown, ordered chronologically, with the clicked/source item sitting in the middle of the grid ("hiện đầy hết grid luôn ấy"). Confidence: 0.65
- Wants instructions executed directly instead of debated: when a constraint he already knows about gets raised, he prefers the requested implementation be built as asked (he'll handle limits himself) rather than the assistant re-litigating the constraint or proposing alternative architectures. Same for scope: build exactly what was asked, with no self-invented extras such as corpus filtering or subset runs ("cứ làm theo tôi bảo", "cứ làm theo tôi nói đi"). This also covers extended fact-finding: when he states how a platform behaves (e.g. Kaggle unzips uploaded zip files), he expects it to be taken as given and the action performed, not researched further first — and he will repeat the same instruction verbatim if the assistant keeps probing instead of acting. Confidence: 0.9
