# Taste

- When he wants to compare two approaches, prefers a parallel duplicate of the pipeline (its own config file and artifacts directory) so he can judge results himself, rather than a benchmark/AB-comparison mode bolted onto the existing pipeline. Judge-it-himself means run both on one real, realistically long video from the actual corpus (not a synthetic toy clip) and hand him the side-by-side output folders to eyeball, rather than declaring a winner from aggregate metrics. Confidence: 0.75
- Once he has eyeballed a comparison and says it's good, he wants the old/superseded implementation removed outright and the winner made the single main path — not kept alongside as a fallback or dual-backend option. Confidence: 0.6
- When he asks for a component (e.g. "làm ra một web ui đầy đủ"), wants the complete user-facing version built now; pushing back with a trimmed "core" scope plus deferral to a later phase reads as under-delivering. Confidence: 0.6
- When local state (a DB, index, artifact dir) is corrupted, prefers the blunt reset — delete the broken state and re-run the normal full pipeline command — over the assistant's surgical, step-by-step repair procedure (exact-row deletes, sequence resets, ordered `--only` runs). Confidence: 0.5
- Wants instructions executed directly instead of debated: when a constraint he already knows about gets raised, he prefers the requested implementation be built as asked (he'll handle limits himself) rather than the assistant re-litigating the constraint or proposing alternative architectures. Same for scope: build exactly what was asked, with no self-invented extras such as corpus filtering or subset runs ("cứ làm theo tôi bảo"). Confidence: 0.8
